# THE LION v0.2
Node 22+. Run npm install, npm test, npm start. Dashboard http://127.0.0.1:8790.
Manual paper practice with $100 virtual cash, whole shares, one position, two closed/opened trades per ET day, $5 daily planned loss and $2.50 per trade. The data/paper.json file stores journal, simulated positions, outcomes, rejected requests, lessons and stop/resume events. It is ignored by Git. Do not delete it. Manual prices are not live or verified. No automatic fills, settlement simulation, verified exchange calendar, data scanner, or strategy engine yet. Daily report shows realized results and position, not live unrealized P&L. Do not treat manual practice as a verified trade proposal.
Robinhood: npm run robinhood:connect starts an experimental official MCP OAuth discovery probe on loopback port 8791. Review requested permissions before approving. Do not fund the dedicated MCP account. If broader account permissions are unacceptable, cancel. Tokens are held in memory and discarded at exit. The probe only lists approved market-data tool schemas; it does not call account/order tools or connect the dashboard to live data. Authentication, schema, freshness, and feed coverage require verification with your account. No real execution code. Official reference: https://robinhood.com/us/en/support/articles/trading-with-your-agent/

## v0.3 monitor foundation
Start and stop the local monitor, edit symbols and interval, emergency stop also blocks paper entries. Existing paper journal is preserved. Research indicator module validates normalized snapshots, excludes incomplete bars and computes EMA, RSI, supplied-bar VWAP (not necessarily full-session VWAP), spread and relative bar volume (not historical same-time RVOL). No actual Robinhood adapter is wired: monitor explicitly reports insufficient data until authenticated schemas, quote timestamps, session calendar and candle normalization are verified. Ollama qwen3:8b explanation function is implemented but not called without a verified provider. No external news endpoint is assumed: Robinhood documents equity news as built-in only. No auto fills, live chart rendering, alerts, full scanner, holiday feed or configurable paper risk settings yet. Run npm test. No deployment. Existing Node/browser architecture retained to avoid breaking v0.2.

## v0.5 opportunity research
Leaderboard ranking uses heuristic scores, not probabilities: momentum = clamp(50 + 1000*(EMA9/EMA21-1) + 2000*(close/VWAP-1) + 10*(relative bar volume-1)); risk = clamp(10000*spread + 2*max(RSI-70,0) + 15 if sideways); rank = clamp(momentum - .5*risk + candidate bonus - sideways/avoid penalties). Consolidation default 20 min, configurable 15–60 in 5-minute increments: range <=0.6%, drift <=0.25%, mean volume <=85% of preceding equal window. These are unvalidated research heuristics. Stale data is rejected first. Existing candidates remain in the configured watchlist. Next evaluation level is resistance, not an entry trigger. Candidate gate requires independent verified target, market trend, asset and account state; current monitor deliberately supplies no account state or verified provider, so no BUY candidates are emitted. No automatic symbol discovery or real-time alert triggering until a verified Robinhood adapter exists. Risk settings remain existing fixed caps. No real orders.

## v0.6 daily control foundation
Daily paper session settings, allocation preview, start/pause/stop/emergency, server-side allocation and loss checks, session reports, allowed/excluded symbols. Legacy fixed $100/$5/two trades/one position caps remain hard ceilings. Automatic mode is explicitly BLOCKED; spread/time/exit settings are stored for future verified market engine, not enforced for manual hypothetical fills. No historical replay, partial fill model, settlement engine, or live execution yet. Report drawdown uses closed trade equity only, not marked-to-market. Existing journal stays intact.
